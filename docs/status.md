# Implementation status and operating limits

The core application works locally and its owner-authenticated backend is deployed. Production file storage uses MongoDB Atlas through Vercel; hosted connectivity, private resume upload/download and live source ingestion have passed. The 15-minute schedule is enabled, with provider-specific polling intervals and backoff. See vercel.md for the deployed architecture. The original architecture and API files preserve the design, not an assertion that every proposed feature is finished.

## Implemented contract differences

- Job lists use limit/offset, not opaque cursors. Optimistic edit versions travel in JSON request bodies, not If-Match.
- Natural unique keys prevent duplicate applications, resume versions, source references, provider messages and notification intents. Generalized Idempotency-Key header handling is not implemented.
- Tailoring selects and reorders owner-verified facts deterministically. No LLM is required or called. Target-job preferences are never inserted as actual resume skills.
- Gmail uses bounded metadata/snippet polling with overlap, rather than push events or a full MIME/LLM pipeline. Exact company/role evidence and a matching application-host sender are required for automatic advancement; ambiguous messages remain reviewable through the API. This is conservative matching, not perfect employer identity verification.
- Sheets owns a dedicated Shortlist tab; manual edits there can be overwritten. D1 is authoritative.

## Remaining features

GitHub job-list ingestion, fuzzy duplicate review, advanced analytics, graphical email review, full follow-up editors, richer manual-override controls and automatic artifact retention/orphan cleanup remain future work. Backend follow-up, correction and email-resolution APIs exist, but dedicated complete UI workflows do not.

PDF/DOCX resume parsing is unverified until the owner verifies profile facts. Use Settings → Verified profile → Import from uploaded resume to draft empty fields, then review and save them. Scanned/encrypted PDFs or documents over 20 pages can require manual entry. PDF output embeds Carlito; scripts outside its glyph coverage need an additional font. DOCX preserves Unicode. Resume removal is soft and retains files/metadata for application provenance.

## Recovery and troubleshooting

Source sync stores partial pagination state and does not advance completion on failure. Each FreeHire run fetches at most three pages of 50 records. Downtime lookback is capped at 30 days. Unknown geographic restrictions stay out of recommendations. A small rotating detail check verifies availability; records unverified for seven days become UNKNOWN rather than falsely CLOSED.

The D1 outbox recovers incomplete work and Queue tasks validate revisions. Bounded source runs now queue their own continuation, and queue consumers continue dispatching pending analysis work. Individual malformed source records are quarantined privately in R2; majority-invalid pages stop for schema review. Missing company names are labeled as not provided. Demo records are hidden unless the API caller explicitly requests demo=true. Inspect the dead-letter queue for exhausted deliveries. Resume render/storage failures retry up to three attempts. Pending scores after profile/settings changes are expected until reanalysis finishes.

Telegram intents are unique, explicit failures can retry, and timeouts become UNKNOWN. Exactly-once external delivery is not guaranteed. A crash after entering SENDING may need manual reconciliation against the chat before retrying. Never resend an uncertain notification blindly.

If the dashboard cannot reach the API, check ports 5173 and 8787. An Origin error means APP_ORIGIN differs from the browser origin. AUTH_NOT_CONFIGURED means the production owner/Access configuration is incomplete. If Discover is empty, inspect Review, remote restrictions, availability and ignored jobs. A visible Google connection only proves encrypted credentials exist, not that refresh remains authorized.

No Telegram messages, Gmail reads, Sheets writes, job applications or production deployment were performed against the owner's live accounts during development. Integration tests use fictional isolated records. Live provider failures, rate limits and actual account permissions still need staging tests.

## Reference resume format

Generated PDFs use the supplied resume style: US Letter, 0.45-inch side margins, embedded Carlito regular/bold/italic, centered name and contact header, ruled uppercase headings, compact hanging bullets, italic employers and right-aligned dates. Section order is Professional Summary, Experience, Projects, Technical Skills, Education; verified achievements appear only when provided. Long content continues onto additional pages rather than being clipped or deleted. The four supplied reference resumes each fit on one page through the actual import/tailor/render pipeline.

Settings → Profile now includes role/headline, professional summary and technical skill groups. A dated entry uses a title/date line, an employer line for experience, then bullet lines beginning with `•` and a `Tech:` line for projects. Keep dates at the end of the heading, for example `API Project 09/2026`. Inline `**bold**` is supported. PDF import reconstructs visual reading order and preserves bold emphasis. Import produces a draft and preserves existing verified fields; review and save before generating. No claims are added from a job description. Existing generated files stay in the library; Generate Resume creates a version using the new template instead of reusing an old-template cache entry.

DOCX uses the corresponding Letter layout, typography and paragraph styles. Its ZIP/XML structure and Worker download path are tested. Visual DOCX rendering could not be verified on this Windows host because LibreOffice is unavailable; Word/font substitution may change pagination. The PDF preview was rendered and visually checked. Carlito's SIL Open Font License is included in `apps/worker/src/fonts/OFL.txt`; its complete fonts are embedded in PDF output for reliable glyph rendering.

## Expanded discovery and matching

FreeHire is joined by Himalayas, Jobicy and Remotive plus company-board adapters for Greenhouse, Lever and Ashby. The initial company watchlist includes Stripe, Canonical, Supabase, Linear, PostHog and Palantir; those public boards were checked during implementation. Settings → Integrations lets the owner enable/disable individual feeds and add a company board name. No API key is required for these public adapters. Sync real jobs queues all enabled sources. Existing profile, applications and resume files are retained; source registration is additive and needs no new migration.

Himalayas searches engineer/developer/SDE roles available to India, including worldwide results, and checks the returned country and UTC+05:30 restrictions locally. Search pagination continues until an empty page for each query. Jobicy uses its opaque cursor and Lever uses offset pagination. Large company responses are cached privately in R2 and processed 25 records per task; completed cached pages are removed. Published Ashby posts marked unlisted are excluded. Invalid contracts are quarantined; majority-invalid batches fail visibly. Each feed has its own lease, cursor, error and retry state. Expired or invalid cursor/cache state starts a fresh traversal after backoff. One feed failing does not block another.

Public feeds honor provider attribution/application links. Himalayas refreshes at most daily; Jobicy, Remotive and company boards at most every six hours. The Cloudflare cron still ticks every 15 minutes to queue due work, not to bypass provider intervals. Local development has no automatic cron: click Sync real jobs. The Remotive public feed has a 24-hour delay and its available results can be limited. Source polling frequency does not guarantee immediate publication or closure detection. New-feed positive refreshes update last verification; otherwise the existing seven-day UNKNOWN policy applies. Geographic ambiguity remains outside Discover. Non-development titles are counted as skipped by the new adapters, so scanned and stored counts differ.

The patterns-2 matcher recognizes role families and canonical technology aliases, separates verified skill overlap from search preferences, and exposes evidence and missing skills. Role 20 + experience 15 + preferred technology overlap 30 + location 5 + verified skills 25 + freshness 5 = 100 maximum. Country, timezone, availability and the two-year hard cap remain prerequisites. Missing experience stays uncertain; an excellent stack match cannot override it. Discover offers source filtering and best-match/newest sorting. Scores are heuristic rankings, not probabilities of getting hired. Sync queues updates for existing eligible scores from an earlier engine. Specific canonical application URLs merge duplicates across sources; fuzzy title/company matches are not automatically merged.

Validation: unit/contract tests cover every adapter, geographic restrictions, invalid URLs, role/skill aliases, missing experience, cursor behavior and evidence. The isolated multi-source Worker test covers queue continuations, R2 caching, rate-limit isolation, source toggles, polling intervals, deduplication, filtering and stale-status recovery. The standard integration command includes this suite. First-page live responses from all nine configured external feeds normalized successfully (1,371 returned records at the time of checking); this read-only probe did not import them into the owner's running database. No claims are made about how many will pass the owner's filters. UI builds and API tests passed; live local use requires restarting the server to load the new Worker.

## Background refresh and application helper

Review/Discover no longer replace the result list with the full-page loading state when data is refreshed. Sync progress polls update the progress control only; the shared results refresh fires once when client-side polling finishes. The data hook preserves cached results during background requests and temporary failures, aborts superseded filter requests, and ignores late responses. Existing card DOM, focus and scroll remain intact. Update results lets the owner request another nonblocking refresh while a longer source sync continues in the background.

The packaged Shortlist Application Helper is an unpacked Manifest V3 Chrome/Edge extension. Download it from Settings → Verified profile or use the ZIP beside the source deliverable. Load the extracted folder through the browser's Extensions → Developer mode → Load unpacked. The app cannot silently install it. It is not published in an extension store.

Import the saved verified profile directly while the Shortlist dashboard is the active tab, or download the owner-authenticated `/api/v1/profile/autofill` JSON export and import that file. Edit derived name parts, location and education/current-role details before use. Profile and optional PDF/DOCX resume are stored in browser-local extension storage; no external autofill service or cross-device sync is used. The extension requests only activeTab, scripting and storage; it has no persistent host permissions or automatic content scripts. Packaged code is injected only on user action. Preview fields, deselect any unwanted suggestions, then fill. Existing answers, sensitive screening fields, consent boxes and submit controls are excluded. Optional resume attachment targets Resume/CV file fields. Undo preserves subsequent edits. Custom controls and inaccessible frames may need manual entry.

Validation includes 12 DOM regression tests for cached background refresh, request races, polling refresh frequency, field classification, preserving answers, selects, native React-controlled input events, resume files, shadow roots/same-origin frames, undo and the permission manifest. An isolated actual-Chrome check with local fixtures also verified Review sync without loading flashes/focus loss and native form/file filling. The popup was rendered with mocked Chrome storage. These checks do not claim that the unpacked extension has been installed in the owner's browser or tested against every live ATS. The profile export is included in Worker integration tests.
